## 1. What the artifact actually is

The supplied file is *not* an APK. It is a **three-layer container** — a detail that
most write-ups get wrong:

| Layer | Object | Bytes | SHA-256 (prefix) |
|---:|---|---:|---|
| 0 | `Zalopay-…_APKPure.zip` (ZIP, deflate) | 98,813,878 | `see data/inventory_summary.json` |
| 1 | `…_APKPure.xapk` — APKPure *split bundle*, `xapk_version: 2` | 105,608,128 | idem |
| 2a | `vn.com.vng.zalopay.apk` — base module (`base`) | 79,359,087 | idem |
| 2b | `config.armeabi_v7a.apk` — ABI split, 32 entries | 24,828,408 | idem |
| 2c | `config.en.apk` / `config.vi.apk` — locale splits | 74 KB / 86 KB | idem |
| 2d | `config.xhdpi.apk` — density split, 258 entries | 1,232,563 | idem |
| 2e | `manifest.json`, `icon.png` — XAPK metadata | — | idem |

**Totals:** `6,472` archive entries · `381.2 MiB` (399,749,315 B) of uncompressed
content across the three layers.

The base module alone carries **19 `classes*.dex`** files (~74 MB of Dalvik
bytecode) plus an `assets/audience_network.dex` payload that is *not* referenced by
the class loader at build time — a Meta Audience Network artefact that survives
packaging.

```
classes.dex      8,831,004   classes11.dex   163,420   classes16.dex   15,916
classes2.dex    16,516,960   classes12.dex   398,276   classes17.dex  208,476
classes3.dex       850,600   classes13.dex   145,824   classes18.dex   95,920
classes4.dex     9,418,124   classes14.dex    81,748   classes19.dex  719,548
classes5.dex     7,357,484   classes15.dex    82,152   audience_network.dex 4,864,036
classes6.dex     7,612,432   classes7.dex  10,803,680   classes8.dex  239,036
classes9.dex     1,218,908   classes10.dex    78,204
```

`targetSdkVersion 36`, `minSdkVersion 26` — i.e. built for Android 16 while retaining
Android 8.0 compatibility, which is why so much legacy crypto and
`armeabi-v7a`-only native code is still shipped.

## 2. Pipeline architecture

```
analysis/pipeline/
├── common.py          shared hashing, entropy, magic-detection, JSON helpers
├── 01_inventory.py    every entry in every container layer + entropy profile
├── 02_manifest.py     binary AXML → component/permission/export census
├── 03_dex.py          19 DEX files → class/method/string/type census
├── 04_sdk.py          third-party SDK & tracker fingerprinting
├── 05_secrets.py      credential-shaped string discovery (redacted)
├── 06_native.py       ELF headers, imports, symbols, capstone disassembly
├── 07_resources.py    resource table, locale coverage, asset classes
├── 08_graph.py        cross-DEX reference graph & package coupling
├── 09_findings.py     risk model → findings.json consumed by the video
└── 10_report.py       Markdown/HTML dossier generation
```

Run the whole chain with:

```bash
python3 analysis/pipeline/run_all.py
```

The only third-party dependencies are `androguard`, `lief`, `capstone` and
`imageio-ffmpeg` (see `analysis/requirements.txt`).

## 4. Ethics & responsible disclosure

* Only **static** analysis of a **publicly distributed** APKPure build was performed.
* No attempt was made to defeat TLS, extract live credentials, or contact Zalopay
  infrastructure. Secret-shaped strings are reported **redacted** (length + SHA-256
  fingerprint only) so the dossier is auditable without leaking.
* Native-code findings describe *capability*, not *intent*.
* This repository is research; it is not affiliated with VNG Corporation or Zalopay.
